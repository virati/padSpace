padSpace pad map: Launchpad Mini MK3, main at 300d507

Every pad and round button on the Launchpad, what it does in each mode, and what its light means. Everything here is read from the daemon on main at commit 300d507 (2026-09-29).

The pad, by mode

Workspace grid (top two pad rows, always on)

The top two pad rows are two 2×4 grids, one per display. Each grid is fixed to its display by screen order, not by focus.

PadsDisplayDesktops
81–84 / 71–74Screen 0: HDMI-A-1, the ultrawide (left grid)1–4 on top, 5–8 below
85–88 / 75–78Screen 1: eDP-1, the laptop (right grid)1–4 on top, 5–8 below
  • Tap switches that display to that desktop.
  • Hold for 0.55 s or longer also moves the window you were using to that desktop. Holding a pad on the other grid moves the window to the other display. The pads have no velocity sensing (every hit sends 127), so hold time stands in for pressing hard.

White wins over the app colors. When several apps are on one desktop, the earliest rule in MARKERS wins, unless MARKER_COMBOS names that pair. Updates come from a KWin script that reports within about 10 ms of a desktop switch, window move or title change. A 5 s poll is only a backup.

How the agent flash works

Added on 2026-09-29 (PR #2). The flash alternates with the pad's normal color, so the current desktop still reads white. Red wins over green on a shared pad.

  • Hook. ~/.local/bin/padspace-agent-hook is a Claude Code hook on Stop, StopFailure, Notification, UserPromptSubmit and PostToolUse. It writes each session's last state to ~/.local/state/padspace/agents/<session_id>.json. tools/install-agent-hooks.py adds it to ~/.claude/settings.json, and --remove takes it out.
  • Session file. ~/.claude/sessions/<pid>.json tells the daemon which process each session is and whether it is idle. Its waiting status also counts as red. It is not enough on its own, because a tool-permission prompt leaves it at busy.
  • Which pad. The session's pad is the desktop of the window it runs in: the window whose pid is one of the session process's parents (its Konsole).

Seen on the device: green, from a real Stop hook, on 2026-09-29. Not yet seen: red from a real permission prompt, and green clearing on focus. Only sessions on this machine count; Polaris sessions have no local window.

The four mode buttons are toggles, and only one can be on at a time. Turning one on turns the others off. With all four off, the bottom rows are dark and only the workspace grid is live. That is also how the daemon starts.

Session (cc95)

Bottom row (11–18): Claude Code sessions on this machine. Second row (21–28): your own sessions on Polaris, checked over SSH every 6 s in a background thread. Other users' Polaris sessions are never shown. Green means the last tool result had no error, red means it did, and dim white means the transcript could not be read. Pressing a pad focuses that session's window and switches to its desktop. If there is no window (always the case for Polaris), it opens a new Konsole running claude --resume.

Pressing a Session pad has not been tried on the device yet.

Drums (cc96)

Sixteen synthesized 909/808-style samples, preloaded into PipeWire when the mode turns on. Bottom row: kick-punch, kick-sub, kick-hard, snare, clap, hat-closed, hat-open, crash. Second row: sub-drop, tom-low, tom-high, shaker, pluck, snap, ride, reverse-cymbal. To change a sound, replace the same-named WAV in ~/.local/share/padspace/drumkit/ and toggle Drums again.

Keys (cc97)

A numpad in the bottom-left 3×4 block: 7 8 9 / 4 5 6 / 1 2 3, and a wide 0 across the three bottom pads. Each digit pad breathes green once every N seconds (pad 7 every 7 s); the 0 row glows steadily.

User (cc98)

Bottom row, amber: Claude Code skills from ~/.ctrl/claude/. Second row, blue: Hermes skills from ~/.ctrl/hermes/. Up to 8 per row, sorted by the number prefix, re-read every time the mode turns on. A press opens a Konsole with that skill. Today the rows hold constellupdates, coremap, padspace, linear-issue, and research, productivity, note-taking, devops.

Your own commands on any free pad

Any pad outside the workspace grid, and any of the right-hand round buttons (cc19–89), can run a shell command. Add lines to ~/.config/padspace/bindings.conf; the file reloads within about 3 s.

36 = konsole                      # pad 36 opens a terminal
12 @13 = playerctl play-pause     # pad 12, lit yellow (palette 13)
cc59 @5 = loginctl lock-session   # right-column button, lit red
  • Bound pads stay lit (blue by default) and flash white on press. Commands run detached through systemd-run --user.
  • The workspace grid (71–78, 81–88) and the top round row (cc91–98) are reserved. A binding on them is logged and ignored.
  • When a mode is on, it owns its pads. A binding on the bottom two rows only fires while all four modes are off.
  • No bindings are set today.
  • To find a button's number, press it and look for the "unbound pad note N" or "unbound control ccN" line in the daemon log.

The same view in a terminal

ls-ws lists the windows on each desktop, per display. --desc adds a one-line summary per desktop, --prompts shows each Claude session's status and last prompt, and --banner shows a 30 s summary at the top of the screen.

Files: daemon bin/launchpad-workspaces, installed at ~/.local/bin/launchpad-workspaces; unit launchpad-workspaces.service; repo ~/Projects/padSpace (github.com/virati/padSpace).
